Hermes Agent Stack — Architecture Guide

Long image

A

Answer

The Hermes course stack is a three-service Docker Compose system — agent, AI gateway, and long-term memory — wired so one credential in .env powers everything.

  1. A single GTW_API_KEY is shared by Hermes, OmniRoute, and Hindsight.
  2. All inter-service traffic stays inside hermes-net (bridge); only ports :9119, :20128, :8888, and :8642 are published to the host.
  3. The agent and its web dashboard run as co-supervised processes inside one container; splitting them across containers caused dual SQLite writers and a gateway socket race.

How does a request flow from prompt to response?

Diagram structure
  • User user
  • Hermes Agent hermes
  • OmniRoute omniroute
  • Hindsight hindsight
  • LLM Provider llm
  • user → hermes · send prompt
  • hermes → hindsight · recall memories
  • hindsight → hermes · context snippets
  • hermes → omniroute · POST /v1/chat/completions
  • omniroute → llm · HTTPS request (fallback tiers)
  • llm → omniroute · completion
  • omniroute → hermes · streamed response
  • hermes → hindsight · POST /retain (async)
  • hermes → user · agent reply
  1. Recall memories ↗

    Hindsight is queried before inference so the conversation gets long-term context injected.

  2. Call OmniRoute ↗

    Hermes posts to /v1/chat/completions with the bearer token from CUSTOM_API_KEY. OmniRoute selects an upstream, applies fallback tiers, and streams the response.

  3. Retain key facts ↗

    After answering, Hermes asynchronously retains key facts. Hindsight runs entity extraction via OmniRoute — the same credential loop.

Optional API serverStatic bearer keyAPI_SERVER_KEY in .env (disabled by default)

OmniRoute always checks its own key database

OMNIROUTE_REQUIRE_API_KEY=false does not disable bearer-token checking on /v1. Any request must carry a key created in the OmniRoute dashboard under Endpoints. The omniroute-local placeholder in .env.example is not a valid key.

How do you start and verify the stack?

Hindsight boots last

hermes depends on hindsight with condition: service_healthy. The first boot takes 1–2 minutes while Hindsight initialises PostgreSQL and runs migrations. Check progress with docker compose logs -f hindsight.
